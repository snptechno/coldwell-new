## Upload rules

`Ui_model::save_partner_us` (models/ui/Ui_model.php:178) is dropped (no caller), so nothing has to be rebuilt now. Its rules, for reference if the partner form comes back:

- Field: `document_file`.
- Order: the `partner_with_us` row is inserted first; the file is handled afterwards, and on success `attachment_file` of that row is updated with the new file name. On a rejected or failed file the row stays without an attachment.
- Target directory: `uploads/partner_us/` (under the document root + `FOLDER_NAME`).
- Allowed extensions: `gif`, `jpeg`, `jpg`, `png`, `pdf`, `doc`, `docx`. The extension is the second dot-separated part of the client file name (`explode('.', $name)[1]`), compared case-sensitively. No MIME check.
- Size limit: under 2,000,000 bytes.
- File name: `time() . rand() . '.' . $extension`.
- Old file: none unlinked.
- On rejection the model printed an error text (output belongs to the controller).

A rebuild with CI4 UploadedFile should validate the real extension and MIME type (`ext_in`, `mime_in`, `max_size`) and use `getRandomName()`.

No other function in this domain handles files.

## Notes for the controller step

- **Mail**: every public enquiry action (`Home::franchisee_enquiry`, `contact_enquiry`, `contact_enquiry_popup`, `nri_enquiry`, `franchisee_details_enquiry`) sends a notification mail after the insert, with SMTP settings written in the controller. Move the mail settings to `.env` / `Config\Email` and the sending to the controller or a service, not the models.
- **Responses**: `Home::franchisee_enquiry` echoes `Success`; `contact_enquiry_popup` echoes `1` and exits; `nri_enquiry` echoes `Success` and exits; `contact_enquiry` (`lp_name` branch) exits; the other actions set flashdata (`class`, `message`) and redirect (`contact-us#cont-right`, `$url . '#franchisee'`, `HTTP_REFERER`, `newsletter#media`). Admin delete actions set `success_msg` flashdata and redirect to their list; `save_project_contact` sets `description_success_msg` and redirects to `admin/section/update_contact/{project}/{id}` or `admin/section/list_projects/`.
- `Home::franchisee_enquiry` (controllers/Home.php:186) has a debugging `print_r(...); die;` before the insert, so the action never saves in CI3. Decide whether to restore the intended save.
- `Home::contact_enquiry`, `interest` branch (controllers/Home.php:285-303): builds `franchisee_id` from an undefined `$id` and uses keys `email_id`, `created_date`, `franchisee_id`, which are not columns of `contact_enquiry`. In CI3 the insert fails with a database error. Through the CI4 Model those keys are filtered out by `allowedFields` and the row would be saved without the email. The controller should map the data to `email` (or send it to `FranchiseeProjectEnquiryModel` if that was the intent).
- `admin/Section::save_contact_enquiry` (controllers/admin/Section.php:604): its data has `project_name`, which is not a column of `contact_enquiry`. Same effect as above (CI3 database error; CI4 drops the key). The only form posting to a similar URL is in the unused views/home1.php:280 (`home/save_contact_enquiry`, which has no public action).
- `newsletter_subscriptions.created_date` is `datetime NOT NULL` with no default and `Home::newsletter_subscription` only sends `email`. Under strict SQL mode (staging MySQL 8) the insert is rejected; the live rows all hold `0000-00-00 00:00:00`. The controller should pass `created_date => date('Y-m-d H:i:s')`.
- Export actions (`export_to_excell`, `export_franchisee_enquiries_to_excell`, `export_franchisee_project_enquiries_to_excell`): the date range comes from POST `reservation` (`mm/dd/yyyy - mm/dd/yyyy`), split and reordered to `Y-m-d` in the controller. When `$string` is null and no `reservation` is posted, the date variables are undefined (PHP 8 warning) and the CI3 query matched nothing. Validate the two dates (Y-m-d) before calling `byCreatedDateRange*`.
- Admin ids from URL segments (`delete_*/{id}`, `update_contact/{project_id}/{id}`, `save_project_contact/{project_id}/{id}`) should be cast to int in the controller; the model methods take `int`.
- `Home::partner_with_us` loads a view (`partner_with_us`) that does not exist in the CI3 app.
